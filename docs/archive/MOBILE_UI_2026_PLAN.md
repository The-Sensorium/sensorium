# Mobile UI 2026 Improvement Plan

Status: implemented on `feat/mobile-ui-2026` (Phases 0 to 6, uncommitted), no backend changes

Device feedback fixes (same branch): removed the tab active background pill (tint only),
removed the double bottom inset on the room screen (tab bar owns the inset; composer keeps 8px),
and bumped the cluster leave flow buttons to 48px with 16px labels.
Date: 2026-09-21
Scope: `mobile/` only (Expo SDK 57, React Native 0.86, expo-router, React 19)
Basis: Material 3 Expressive, iOS HIG 2025 to 2026, WCAG 2.2 AA
Source of truth: `docs/DESIGN.md`, `docs/ARCHITECTURE.md`, `docs/TECHNICAL.md`, `mobile/README.md`

## 1. Goals

1. All interactive elements meet a 48x48dp minimum hit area (iOS floor 44x44pt only where 48 is impossible).
2. Text meets 2026 readability norms: body 16px with line height 24, secondary 14px with line height 20, captions 12px with line height 16 max, no 10px text, inputs at 16px to avoid iOS zoom on focus.
3. Safe area and keyboard behavior is owned once per screen, with no double bottom gaps above the tab bar and no composer hidden behind the gesture bar or keyboard.
4. Tab bar, headers, dialogs, and sheets follow one consistent pattern.
5. Dark mode text and border contrast passes WCAG AA (4.5:1 for normal text).
6. Add expected 2026 feedback: haptics, skeleton loading, announced errors and empty states, Dynamic Type safety.
7. Keep repo constraints: strict TS, `@/` alias, tokens only from `mobile/src/lib/theme-tokens.ts`, no new colors or typefaces or radii, components never touch Supabase directly, member-only surfaces only.

## 2. Non-goals

1. No visual rebrand, no new color families, no new fonts, no new radii.
2. No navigation restructuring (keep 5 tabs and hidden detail routes).
3. No backend changes: no migrations, no RLS changes, no RPC changes, no Edge Function changes.
4. No web changes in the core mobile phases except documenting token drift where noted. Web-on-mobile follow-ups live in Appendix A and ship as a separate web PR.
5. No generated file edits: do not hand edit files listed in `mobile/README.md` as generated by `npm run sync:db-types`. If a shared helper needs a change, change web source and re-sync, or keep the mobile fix in hand-written files only.

## 3. Constraints and conventions (from AGENTS.md and mobile README)

1. Branch from `develop` as `feat/mobile-ui-2026`, target `develop` in PR. Never branch from `main` or PR into `main`.
2. Conventional Commits (`feat:`, `fix:`, `test:`, `chore:`).
3. Pre-push: `npm run lint`, `npm run test:coverage` (web), `npm run build` from repo root; plus from `mobile/`: `npm run lint`, `npx tsc --noEmit`, `npm test`.
4. Coverage gate in `vite.config.ts` must not regress; never lower thresholds.
5. Tests colocated: `foo.ts` plus `foo.test.ts` or `foo.test.tsx`.
6. Never use em dashes or en dashes in UI copy, code strings, comments, or docs. Use hyphens, commas, or colons.
7. Tailwind style restriction does not apply to mobile directly, but the equivalent rule does: only tokens in `src/lib/theme-tokens.ts`, ported from `docs/DESIGN.md`.
8. If a synced web file changes, run `node mobile/scripts/sync-db-types.mjs --check` and commit regenerated copies. This plan avoids synced files, so that check should pass unchanged.

## 9. Risks and mitigations

1. Dark primary change alters brand feel: get design sign-off on exact hex, paste contrast proof, keep light untouched.
2. 48px controls increase vertical height and push content down: accept for usability, use slop where visual density must stay (reaction chips, avatar links).
3. Dynamic Type wrapping breaks fixed row layouts: prefer `flexWrap` and `flexShrink: 1`, test at large size, avoid new `numberOfLines={1}` on essential text.
4. Keyboard and safe area behavior differs between Expo Go and prod edge-to-edge: verify on dev build, not only Expo Go.
5. Haptics API availability varies: guard calls, keep haptics additive so failure never blocks send, like, or join.
